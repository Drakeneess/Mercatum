# Mercatum V3 — Comercio y procedencia pública

**Estado:** vertical slice de economía y comercio implementado en la rama `main`, para pruebas locales y privadas. **No es una economía con dinero real**, ni una red blockchain, ni un lanzamiento abierto al público.

## Regla de diseño

El Mercado permite comprar algo por su utilidad, por su condición o por una historia espectacular posiblemente falsa. **Las mentiras dentro del juego están permitidas como fenómeno social**, mientras que duplicar objetos o inventar saldo no lo está.

La interfaz diferencia estrictamente:

- **Hecho de servidor:** una modificación de estado, condición o dueño grabada automáticamente por PostgreSQL.
- **Testimonio de jugador:** afirmación textual registrada por una cuenta. Puede estar equivocada o ser deliberadamente falsa; no se vuelve verdadera por aparecer en el registro.

El nombre o identificador del autor permanece atribuido a su cuenta, aunque el personaje original muera.

## 1. Créditos y compraventa

- Cada cuenta recibe **100 créditos ficticios** al registrarse; el saldo persiste entre personajes y después de permadeath.
- PostgreSQL impide saldos negativos y el servidor registra los cambios en `wallet_ledger` con `delta`, `balance_after`, motivo e ID de solicitud.
- La operación es **idempotente** por `(account_id, request_id)`; reenviar una solicitud ya aceptada no vuelve a pagar ni a entregar el mismo artículo.
- El comerciante solo está disponible cuando el personaje está **fuera del edificio** (`phase=outside`). Salir de la pestaña no equivale a extraer.
- El stock inicial es finito e incluye una linterna de emergencia, una llave sin cerradura y guantes de cuero viejo. Los objetos vendidos regresan a ese stock; no se generan copias para reponerlo.
- Cada instancia conserva su UUID y condición. Comprar, vender o transferir desgasta 1 punto de condición; las criaturas de V2 pueden causar daños adicionales.

### Tasación provisional

Para un objeto con precio base `B`, condición `C` entre 0 y 100, y Trato `TRA`:

```text
precio_compra = max(1, ceil(B × (C/100) × (1.15 - 0.025 × TRA)))
precio_venta  = max(1, floor(B × (C/100) × (0.48 + 0.025 × TRA)))
```

Se muestra el **precio real del servidor** antes de confirmar una compra o venta. Son números iniciales de balance, no una valoración absoluta: los jugadores pueden ofrecer cantidades completamente distintas por mercancía histórica.

## 2. Intercambio directo

El dueño de un objeto puede **anunciarlo voluntariamente**. No se publica automáticamente el inventario de todo el mundo.

Los demás solo ven anuncios de exploradores que cumplan una de estas condiciones:

- Ambos están **dentro del Mercado**, con salud positiva y a una distancia máxima de **1 hexágono**.
- Ambos están **fuera del Mercado** y conectados, en la zona comercial exterior abstracta.

Un comprador propone **créditos, otro objeto, o ambos**. La oferta dura 3 minutos. **No transfiere nada hasta que el vendedor la acepta explícitamente**. El comprador puede cancelar y el vendedor rechazar.

La aceptación vuelve a comprobar al servidor: presencia de ambas partes, ubicación, propiedad y publicación del objeto, créditos disponibles y capacidad de carga de cada personaje dentro. Los cambios de monedas y objetos se ejecutan dentro de **una sola transacción SQL** con bloqueo ordenado de personajes, cuentas y mercancía. Una oferta obsoleta falla sin consumir dinero ni generar copias.

La interfaz muestra los términos de intercambio; **no** decide si el precio es justo ni sanciona al jugador por aceptar un mal trato.

## 3. Registro público de objetos

El registro se consulta **únicamente fuera del edificio**. El backend rechaza consultas o anotaciones de un personaje dentro del Mercado, incluso si intenta enviar mensajes manualmente.

Cada objeto tiene un historial `object_events` de tipo `fact` o `claim`.

- **Fact:** lo crea un trigger SQL al registrar o modificar un objeto. Incluye estados, condiciones y cambios de propietario asociados al UUID de la instancia.
- **Claim:** lo crea una persona desde el registro exterior, con máximo 240 caracteres, cuenta autora estable y timestamp.
- Las entradas son **append-only**: PostgreSQL impide `UPDATE` y `DELETE` sobre `object_events`. Un segundo testimonio puede refutar al primero sin borrar nada.
- Se permiten **3 testimonios por cuenta y hora**, como límite básico contra spam.
- La primera migración V3 agrega una **instantánea explícita** del estado de objetos existentes. No inventa eventos retroactivos de V1 o V2.
- Una cuenta se muestra como `Registrante-XXXXXXXX` hasta que existan alias públicos configurables.

**Esto no es una blockchain.** La base registra y dificulta la alteración mediante los permisos normales de la aplicación; un administrador con control completo de PostgreSQL podría modificar registros. No se afirma inmutabilidad criptográfica ni garantía absoluta de procedencia.

## 4. Integración con V1 y V2

- La navaja original, la herencia del depósito y las heridas de V2 permanecen.
- Si una criatura roba una pieza o el personaje muere, el estado real del objeto se registra automáticamente y cualquier anuncio activo queda retirado.
- La cuenta conserva créditos y objetos ya extraídos a través de sucesores; perder la mochila en una muerte no permite recuperarla mágicamente.
- La economía no detiene criaturas ni altera el horario de referencia. **Desconectarse dentro sigue siendo peligroso**.
- Los dos atributos relevantes nuevos son **Trato** (tasación NPC) y la condición persistente de cada objeto. No hay necesidad de falsear efectos de Temple.

## 5. Arranque en Windows

Con Docker Desktop y PostgreSQL ya configurados para V2:

```powershell
cd D:\Mercatum\Mercatum
git status
git pull --ff-only origin main
pnpm install
docker compose up -d db
pnpm dev
```

El servidor aplica **migraciones incrementales**, sin borrar las cuentas ni objetos previos. Next.js: **http://localhost:3500**. Colyseus: **http://localhost:3001**.

Para llegar al comerciante/registro, completa la **extracción de V1** desde la casilla de acceso. Dentro del edificio podrás anunciar mercancía y ofertar a quien se encuentre a un hexágono, pero no consultar la procedencia pública.

### Verificación

```powershell
pnpm build
pnpm typecheck
pnpm test
pnpm --filter @mercatum/server smoke
pnpm --filter @mercatum/server smoke:v1
pnpm --filter @mercatum/server smoke:v2
pnpm --filter @mercatum/server smoke:v3
```

El test V3 crea un **esquema PostgreSQL temporal aislado**, comprueba saldo de inicio, precio y compra únicos, venta al comerciante, publicidad voluntaria, oferta con créditos y trueque, aceptación con consentimiento, ledger de propiedad y dinero de solo adición, testimonios públicos, límites de spam y persistencia después de reiniciar el servidor.

**No utilices `docker compose down -v` si quieres conservar personajes y mercancía.**

## 6. Pendientes

- No hay aún puntuación numérica de reputación, impugnaciones formales, herramientas de reporte ni moderación real de declaraciones. La contradicción existe como nuevos testimonios atribuidos.
- No hay chat de proximidad todavía (hito social posterior); las ofertas sí aparecen en tiempo real.
- No hay reposición automática de stock; el abastecimiento emergente tendrá que diseñarse.
- El desgaste está asociado a transferencias y daño de criaturas, pero no hay envejecimiento ambiental por tiempo ni reparación.
- El archivo exterior no audita por sí solo la integridad frente a administradores de la BD. La decisión blockchain se mantiene como investigación, no requisito.
- La autenticación por token local sin recuperación, la sincronización pública de otros jugadores y el conjunto limitado de controles de abuso **no son adecuados para una alfa abierta**.
